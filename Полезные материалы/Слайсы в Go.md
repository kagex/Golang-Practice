# Слайсы (Slices) в Go

## 1. Определение и мотивация

Слайс (slice) — это дескриптор переменной длины, предоставляющий доступ к непрерывной последовательности элементов одного типа. Слайс не хранит данные непосредственно; он ссылается на базовый массив (underlying array), выделяемый либо явно программистом, либо неявно средой выполнения.

Необходимость слайсов обусловлена ограничениями массивов в Go. Длина массива является частью его типа, что делает невозможным написание обобщённых функций для последовательностей произвольной длины. Слайс решает эту проблему, отделяя представление последовательности от её хранения.

```go
// Массив: длина фиксирована и входит в тип
var arr [1024]byte

// Слайс: длина динамическая, тип не зависит от размера
var s []byte
```

В практике программирования на Go слайсы используются для представления списков, буферов, строк (как `[]byte`), очередей и любых других упорядоченных коллекций. Массивы применяются в специализированных задачах: криптографии, линейной алгебре, низкоуровневой оптимизации.

## 2. Внутреннее представление

Слайс в среде выполнения Go представлен структурой из трёх машинных слов. На 64-битной архитектуре размер заголовка слайса составляет 24 байта.

```go
// Упрощённое представление (src/runtime/slice.go)
type slice struct {
    array unsafe.Pointer // указатель на первый доступный элемент
    len   int            // число доступных элементов
    cap   int            // число элементов от array до конца выделенного блока
}
```

Графически:

```text
Заголовок слайса (24 байта)
┌────────────────┬──────────────┬──────────────┐
│ array (8 байт) │ len (8 байт) │ cap (8 байт) │
└───────┬────────┴──────────────┴──────────────┘
        │
        ▼
Базовый массив
┌───┬───┬───┬───┬───┬───┬───┬───┐
│   │   │ 10│ 20│ 30│   │   │   │
└───┴───┴───┴───┴───┴───┴───┴───┘
              ▲           ▲       ▲
              │           │       │
            array    array+len  array+cap
```

Из данного представления следуют три свойства:

**Свойство 1.** Присваивание слайса копирует заголовок, но не копирует элементы базового массива. Два слайса, полученные присваиванием, ссылаются на одну и ту же память.

**Свойство 2.** Изменение элемента через один слайс видно через любой другой слайс, ссылающийся на тот же участок массива.

**Свойство 3.** Операция `append` может как модифицировать существующий массив (при `len < cap`), так и выделить новый (при `len == cap`). В последнем случае прежний и новый слайсы перестают разделять память.

## 3. Создание и инициализация

### 3.1. Нулевой слайс

Объявление без инициализации порождает нулевой (nil) слайс:

```go
var s []int
// s == nil: true
// len(s) == 0, cap(s) == 0
```

Нулевой слайс функционально эквивалентен пустому для операций `append`, `len`, `cap`, `range`. Различие проявляется при сериализации и проверках на `nil` (см. раздел 8).

### 3.2. Литерал слайса

```go
s := []int{1, 2, 3}
// len = 3, cap = 3
```

Компилятор выделяет безымянный массив из трёх элементов и создаёт слайс, ссылающийся на него целиком.

### 3.3. Функция make

```go
s := make([]int, 5)      // len = 5, cap = 5, элементы инициализированы нулями
s := make([]int, 0, 10)  // len = 0, cap = 10
```

Вторая форма предпочтительна, когда слайс будет наполняться через `append`: предварительное выделение ёмкости исключает промежуточные реаллокации.

### 3.4. Срез из массива или другого слайса

```go
arr := [6]int{0, 1, 2, 3, 4, 5}

s1 := arr[2:5]    // [2, 3, 4], len = 3, cap = 4
s2 := arr[:]      // [0, 1, 2, 3, 4, 5], len = 6, cap = 6
s3 := arr[:3]     // [0, 1, 2], len = 3, cap = 6
s4 := arr[3:]     // [3, 4, 5], len = 3, cap = 3
```

Все четыре слайса ссылаются на память массива `arr`. Модификация `s1[0]` изменяет `arr[2]`.

### 3.5. Полное выражение среза

Трёхиндексная форма `s[low:high:max]` позволяет ограничить ёмкость результирующего слайса:

```go
arr := [6]int{0, 1, 2, 3, 4, 5}
s := arr[1:4:4]
// len = high - low = 3
// cap = max - low  = 3
```

При `cap = 3` любой вызов `append`, выходящий за пределы трёх элементов, гарантированно инициирует реаллокацию. Это предотвращает случайную перезапись элементов `arr[4]` и `arr[5]`, которая произошла бы при `cap = 5`.

## 4. Операции над слайсами

### 4.1. Индексация

Доступ к элементу осуществляется по индексу от `0` до `len(s) - 1`. Обращение за пределами диапазона вызывает панику времени выполнения (`index out of range`).

```go
s := []int{10, 20, 30}
s[1] = 99   // допустимо
// s[3] = 1 // паника: index out of range [3] with length 3
```

### 4.2. Функция append

`append` добавляет один или несколько элементов в конец слайса и возвращает результирующий слайс.

```go
s := []int{1, 2}
s = append(s, 3)          // [1, 2, 3]
s = append(s, 4, 5, 6)    // [1, 2, 3, 4, 5, 6]

other := []int{7, 8}
s = append(s, other...)   // [1, 2, 3, 4, 5, 6, 7, 8]
```

Повторное присваивание результата обязательно. Если `len(s) < cap(s)`, элемент записывается в существующий массив, и присваивание формально избыточно. Однако если `len(s) == cap(s)`, среда выполнения выделяет новый массив, и без присваивания вызывающий код продолжит ссылаться на прежний. Поскольку программист не контролирует, какой из двух случаев имеет место, результат `append` присваивается всегда.

### 4.3. Функция copy

Встроенная функция `copy` копирует элементы из одного слайса в другой:

```go
src := []int{1, 2, 3, 4, 5}
dst := make([]int, 3)
n := copy(dst, src)
// dst = [1, 2, 3], n = 3
```

Число скопированных элементов равно `min(len(dst), len(src))`. Функция корректно обрабатывает перекрывающиеся слайсы (копирование внутри одного массива).

Необходимость `copy` обусловлена тем, что оператор присваивания `dst = src` копирует заголовок, а не данные. После присваивания `dst` и `src` ссылаются на один массив. Если требуется независимая копия данных, используется `copy` либо (в Go 1.21+) функция `slices.Clone`.

### 4.4. Длина и ёмкость

```go
s := make([]int, 3, 10)
len(s) // 3
cap(s) // 10
```

`len` определяет число элементов, доступных для чтения и записи. `cap` определяет максимальное число элементов, которое может вместить слайс без реаллокации.

## 5. Семантика передачи в функции

Слайс передаётся в функцию по значению. Значением слайса является его заголовок (24 байта). Базовый массив не копируется.

```go
func modify(s []int) {
    s[0] = 999       // модифицирует общий массив
    s = append(s, 1) // модифицирует локальную копию заголовка
}

data := []int{1, 2, 3}
modify(data)
// data[0] == 999 — изменение по индексу видно вызывающему коду
// len(data) == 3 — изменение длины может быть не видно
```

Вторая строка функции `modify` демонстрирует асимметрию. Если `append` не вызывает реаллокации, новый элемент записывается в общий массив, но поле `len` обновляется только в локальной копии заголовка. Вызывающий код не наблюдает изменения длины. Если `append` вызывает реаллокацию, новый массив не разделяется с вызывающим кодом вовсе.

Для функций, изменяющих длину слайса, приняты два соглашения:

```go
// Вариант 1: возврат модифицированного слайса
func push(s []int, x int) []int {
    return append(s, x)
}
s = push(s, 42)

// Вариант 2: указатель на слайс
func push(s *[]int, x int) {
    *s = append(*s, x)
}
push(&s, 42)
```

Первый вариант идиоматичен и предпочтителен в большинстве случаев.

## 6. Управление памятью

### 6.1. Утечка через удержание базового массива

Слайс удерживает ссылку на весь базовый массив, а не только на доступные элементы. Если из массива размером N байт создан слайс на k элементов, сборщик мусора не может освободить ни одного из N байт, пока жив этот слайс.

```go
// Функция возвращает 10 байт из буфера размером 1 ГБ
func header(buf []byte) []byte {
    return buf[:10]
}
```

Возвращённый слайс имеет `len = 10`, но его `ptr` указывает на начало буфера. Весь буфер остаётся достижимым и не подлежит сборке.

Корректный подход — копирование необходимых данных в новый слайс:

```go
func header(buf []byte) []byte {
    out := make([]byte, 10)
    copy(out, buf[:10])
    return out
}
```

После этого `buf` не имеет ссылающихся на него слайсов и может быть собран.

### 6.2. Стратегия роста

При исчерпании ёмкости `append` выделяет новый массив. Стратегия определения нового размера зависит от версии Go. Начиная с Go 1.18:

- при `cap < 256` новая ёмкость приблизительно удваивается;
- при `cap >= 256` рост составляет примерно 25% плюс аддитивная константа.

Конкретные коэффициенты не гарантированы спецификацией и могут изменяться между версиями. Программисту следует опираться не на точные значения, а на принцип: многократный `append` без предварительного выделения ёмкости приводит к серии реаллокаций, каждая из которых включает аллокацию, копирование и создание мусора.

```go
// Неэффективно: O(log n) реаллокаций
var s []int
for i := 0; i < n; i++ {
    s = append(s, i)
}

// Эффективно: одна аллокация
s := make([]int, 0, n)
for i := 0; i < n; i++ {
    s = append(s, i)
}
```

### 6.3. Размещение в стеке и куче

Если слайс не покидает область видимости функции (не возвращается, не присваивается глобальной переменной, не захватывается замыканием), компилятор может разместить базовый массив на стеке. Анализ утечек (escape analysis) выполняется автоматически; программист может наблюдать его результаты через флаг `-gcflags="-m"`.

## 7. Идиоматические операции

### 7.1. Удаление элемента

Удаление без сохранения порядка. Элемент заменяется последним, длина уменьшается на единицу. Сложность O(1).

```go
func removeUnordered(s []int, i int) []int {
    s[i] = s[len(s)-1]
    return s[:len(s)-1]
}
```

Удаление с сохранением порядка. Элементы, следующие за удаляемым, сдвигаются влево. Сложность O(n).

```go
func removeOrdered(s []int, i int) []int {
    copy(s[i:], s[i+1:])
    return s[:len(s)-1]
}
```

### 7.2. Вставка элемента

```go
func insert(s []int, i, x int) []int {
    s = append(s, 0)       // расширяем на один элемент
    copy(s[i+1:], s[i:])   // сдвигаем хвост вправо
    s[i] = x
    return s
}
```

### 7.3. Фильтрация без дополнительной аллокации

Подходящие элементы записываются в начало исходного слайса. Возвращается срез до нового логического конца.

```go
func filterEven(s []int) []int {
    n := 0
    for _, v := range s {
        if v%2 == 0 {
            s[n] = v
            n++
        }
    }
    return s[:n]
}
```

Данный приём мутирует исходный слайс. Если это недопустимо, предварительно выполняется `slices.Clone` или `copy`.

### 7.4. Удаление дубликатов из отсортированного слайса

```go
func compact(s []int) []int {
    if len(s) < 2 {
        return s
    }
    n := 1
    for i := 1; i < len(s); i++ {
        if s[i] != s[n-1] {
            s[n] = s[i]
            n++
        }
    }
    return s[:n]
}
```

### 7.5. Пакет slices (Go 1.21+)

Стандартная библиотека предоставляет обобщённые функции для типичных операций:

```go
import "slices"

slices.Contains(s, 42)       // поиск элемента
slices.Sort(s)               // сортировка
slices.Clone(s)              // независимая копия
slices.Delete(s, 2, 5)       // удаление диапазона [2, 5)
slices.Equal(a, b)           // поэлементное сравнение
slices.Index(s, 42)          // индекс первого вхождения
slices.Reverse(s)            // обращение порядка
```

Использование данного пакета предпочтительнее ручных реализаций, поскольку функции обобщены, протестированы и оптимизированы.

## 8. Нулевой и пустой слайс

```go
var a []int           // nil-слайс
b := []int{}          // пустой слайс
c := make([]int, 0)   // пустой слайс
```

| Свойство | nil-слайс | пустой слайс |
| --- | --- | --- |
| `s == nil` | `true` | `false` |
| `len(s)` | `0` | `0` |
| `cap(s)` | `0` | `0` |
| `append(s, x)` | работает | работает |
| `json.Marshal(s)` | `null` | `[]` |
| `for range s` | 0 итераций | 0 итераций |

Различие существенно при проектировании API. Если поле структуры представляет список, который может отсутствовать, используется nil-слайс. Если список всегда присутствует, но может быть пуст, используется инициализированный слайс.

```go
type Response struct {
    Items []string `json:"items"`
}

// Items == nil  → JSON: {"items": null}
// Items == []   → JSON: {"items": []}
```

Для проверки «слайс не содержит элементов» следует использовать `len(s) == 0`, а не `s == nil`, поскольку первое покрывает оба случая.

## 9. Сравнение с массивами

| Характеристика | Массив `[N]T` | Слайс `[]T` |
| --- | --- | --- |
| Длина | Часть типа, неизменяема | Динамическая |
| Присваивание | Копирует все элементы | Копирует заголовок (24 байта) |
| Передача в функцию | Копия данных | Копия заголовка, данные общие |
| Сравнение через `==` | Допустимо (если элементы сравнимы) | Недопустимо (кроме `nil`) |
| Использование как ключ map | Допустимо | Недопустимо |
| Типичное применение | Фиксированные структуры (хеши, матрицы) | Списки, буферы, коллекции |

Слайс нельзя сравнить через `==`, поскольку он является дескриптором, а не значением. Поэлементное сравнение выполняется функцией `slices.Equal` (Go 1.21+) или циклом.

## 10. Рекомендации

1. Предварительное выделение ёмкости. Если итоговый размер известен или оценивается, используется `make([]T, 0, n)`. Это исключает промежуточные реаллокации и снижает нагрузку на сборщик мусора.

2. Присваивание результата append. Запись `s = append(s, x)` обязательна независимо от того, ожидается реаллокация или нет.

3. Копирование при возврате подмножества. Если функция возвращает часть большого буфера, данные копируются в новый слайс. В противном случае весь буфер остаётся недостижимым для сборщика.

4. Использование полного выражения среза. При создании слайса из чужого массива, который не должен модифицироваться через `append`, применяется форма `s[low:high:max]`.

5. Предпочтение пакета slices. Стандартные операции (поиск, сортировка, сравнение, клонирование) реализованы в пакете `slices` и не требуют ручной реализации.

6. Разграничение nil и empty. В публичных API и структурах, сериализуемых в JSON, выбор между nil-слайсом и пустым слайсом является частью контракта.
