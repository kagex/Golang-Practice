# Структуры в Go

Структуры в Go — это составной тип данных, который объединяет несколько полей под одним именем. Структуры используются для моделирования сущностей: пользователя, товара, заказа, конфигурации, HTTP-ответа, координаты и так далее.

Материал опирается на официальную документацию Go: спецификацию языка, Effective Go и документацию пакета `encoding/json`.

---

## 1. Что такое структура

Структура — это тип, состоящий из набора полей. Каждое поле имеет имя и тип.

```go
type Point struct {
 X int
 Y int
}
```

Здесь `Point` — структура с двумя полями: `X` и `Y`, оба типа `int`.

Структура может содержать поля разных типов:

```go
type User struct {
 ID        int
 Name      string
 Email     string
 IsActive  bool
 CreatedAt string
}
```

---

## 2. Нулевое значение структуры

Как и другие типы в Go, структура имеет нулевое значение.

```go
var p Point

fmt.Println(p) // {0 0}
```

Все поля структуры автоматически получают нулевые значения своих типов:

| Тип поля | Нулевое значение |
| --- | --- |
| `int`, `float64` и другие числа | `0` |
| `string` | `""` |
| `bool` | `false` |
| `slice` | `nil` |
| `map` | `nil` |
| `pointer` | `nil` |
| `interface` | `nil` |
| `chan` | `nil` |
| `struct` | нулевая структура |

Пример:

```go
type User struct {
 Name     string
 Age      int
 IsActive bool
 Tags     []string
}

var u User

fmt.Println(u) // {0 false []}
```

Это важная особенность Go: многие структуры специально проектируют так, чтобы их нулевое значение было корректным и удобным для работы.

---

## 3. Создание структуры

### Через переменную

```go
var p Point
p.X = 10
p.Y = 20
```

---

### Через композитный литерал

```go
p := Point{
 X: 10,
 Y: 20,
}
```

Это рекомендуемый способ, потому что он явно показывает, какие поля инициализируются.

---

### Композитный литерал с частью полей

```go
p := Point{
 X: 10,
}
```

Поле `Y` автоматически получит нулевое значение:

```go
fmt.Println(p) // {10 0}
```

---

### Позиционный литерал

Можно указать значения без имён полей:

```go
p := Point{10, 20}
```

Но этот способ требует указать значения для всех полей и зависит от их порядка.

Например:

```go
type Point struct {
 X int
 Y int
 Z int
}

p := Point{1, 2} // ошибка, нужно указать все поля
```

Позиционные литералы лучше использовать только для маленьких и стабильных структур.

---

## 4. Доступ к полям

```go
p := Point{X: 1, Y: 2}

fmt.Println(p.X) // 1
fmt.Println(p.Y) // 2

p.X = 10
```

Если у нас есть указатель на структуру, Go автоматически разыменовывает его при доступе к полям:

```go
p := Point{X: 1, Y: 2}
ptr := &p

ptr.X = 100

fmt.Println(p.X) // 100
```

То есть вместо:

```go
(*ptr).X = 100
```

можно писать:

```go
ptr.X = 100
```

---

## 5. Структуры — это значения

Структуры в Go передаются и присваиваются по значению.

```go
type Point struct {
 X int
 Y int
}

func main() {
 p1 := Point{X: 1, Y: 2}
 p2 := p1

 p2.X = 100

 fmt.Println(p1) // {1 2}
 fmt.Println(p2) // {100 2}
}
```

Присваивание:

```go
p2 := p1
```

создаёт копию структуры.

---

## 6. Передача структуры в функцию

Если передать структуру в функцию, она скопируется.

```go
func move(p Point) {
 p.X += 10
}
```

Изменения внутри функции не повлияют на исходную структуру:

```go
p := Point{X: 1, Y: 2}
move(p)

fmt.Println(p) // {1 2}
```

Если нужно изменять исходную структуру, передают указатель:

```go
func move(p *Point) {
 p.X += 10
}
```

Использование:

```go
p := Point{X: 1, Y: 2}
move(&p)

fmt.Println(p) // {11 2}
```

---

## 7. Указатели на структуры

Указатель на структуру создаётся с помощью оператора `&`:

```go
p := &Point{
 X: 10,
 Y: 20,
}
```

Также можно использовать встроенную функцию `new`:

```go
p := new(Point)
```

`new(Point)` возвращает `*Point`, то есть указатель на нулевую структуру.

Эти варианты похожи:

```go
p1 := &Point{}
p2 := new(Point)
```

Но `&Point{}` удобнее, если нужно сразу задать поля:

```go
p := &Point{
 X: 10,
 Y: 20,
}
```

---

## 8. Экспортируемые и неэкспортируемые поля

Имя поля определяет его видимость.

Если имя поля начинается с заглавной буквы, поле экспортируется и доступно другим пакетам.

```go
type User struct {
 Name  string // экспортируемое поле
 Age   int    // экспортируемое поле
 email string // неэкспортируемое поле
}
```

Поле `email` видно только внутри того пакета, где объявлена структура.

Это важно для:

- инкапсуляции;
- API пакета;
- сериализации в JSON;
- контроля изменений.

---

## 9. Теги структур

Поля структуры могут иметь теги.

Тег — это строка с метаданными, которая не влияет на поведение программы напрямую, но может читаться другими пакетами через reflection.

Пример:

```go
type User struct {
 Name  string `json:"name"`
 Email string `json:"email"`
 Age   int    `json:"age,omitempty"`
}
```

Теги часто используются в:

- `encoding/json`;
- `encoding/xml`;
- ORM;
- валидаторах;
- генераторах документации;
- библиотеках для работы с конфигурацией.

Компилятор не проверяет смысл тегов. Он только сохраняет их как строку. Интерпретация тегов зависит от конкретного пакета.

---

## 10. Структуры и JSON

Пакет `encoding/json` активно использует структуры.

```go
type User struct {
 Name  string `json:"name"`
 Email string `json:"email"`
 Age   int    `json:"age,omitempty"`
}
```

### Сериализация

```go
u := User{
 Name:  "Alice",
 Email: "alice@example.com",
 Age:   30,
}

data, err := json.Marshal(u)
if err != nil {
 log.Fatal(err)
}

fmt.Println(string(data))
```

Пример результата:

```json
{"name":"Alice","email":"alice@example.com","age":30}
```

---

### Десериализация

```go
raw := []byte(`{"name":"Bob","email":"bob@example.com","age":25}`)

var u User

err := json.Unmarshal(raw, &u)
if err != nil {
 log.Fatal(err)
}

fmt.Println(u)
```

Важно:

- сериализуются только экспортируемые поля;
- неэкспортируемые поля игнорируются;
- теги `json:"..."` управляют именем поля в JSON;
- `omitempty` позволяет пропустить поле с пустым значением;
- `json:"-"` полностью исключает поле из JSON.

Пример:

```go
type User struct {
 Name     string `json:"name"`
 Password string `json:"-"`
 Age      int    `json:"age,omitempty"`
}
```

Поле `Password` не попадёт в JSON.

---

## 11. Сравнение структур

Структуры можно сравнивать оператором `==`, если все их поля сравнимы.

```go
type Point struct {
 X int
 Y int
}

p1 := Point{X: 1, Y: 2}
p2 := Point{X: 1, Y: 2}

fmt.Println(p1 == p2) // true
```

Если структура содержит несравнимые поля, например срез, карту или функцию, сравнивать её нельзя.

```go
type User struct {
 Name string
 Tags []string
}

u1 := User{Name: "Alice"}
u2 := User{Name: "Alice"}

// fmt.Println(u1 == u2) // ошибка компиляции
```

Такую структуру также нельзя использовать как ключ в `map`.

Если нужно сравнить поля вручную или использовать особую логику, пишут отдельный метод или функцию.

---

## 12. Структуры как ключи map

Если структура сравнима, её можно использовать как ключ карты.

```go
type Point struct {
 X int
 Y int
}

visited := map[Point]bool{}

visited[Point{X: 1, Y: 2}] = true
```

Это удобно, например, для координат, уникальных идентификаторов, пар значений.

Но если структура содержит срез, карту или функцию, ключом она быть не может.

---

## 13. Методы структур

Структуры часто используются вместе с методами.

Метод — это функция с получателем.

```go
type Point struct {
 X int
 Y int
}

func (p Point) Sum() int {
 return p.X + p.Y
}
```

Использование:

```go
p := Point{X: 3, Y: 4}
fmt.Println(p.Sum()) // 7
```

---

## 14. Получатель-значение и получатель-указатель

Методы могут иметь получатель-значение или получатель-указатель.

### Получатель-значение

```go
func (p Point) Move(dx, dy int) Point {
 return Point{
  X: p.X + dx,
  Y: p.Y + dy,
 }
}
```

Такой метод работает с копией структуры.

---

### Получатель-указатель

```go
func (p *Point) Move(dx, dy int) {
 p.X += dx
 p.Y += dy
}
```

Такой метод изменяет исходную структуру.

---

## 15. Когда использовать указательный получатель

Обычно указательный получатель используют, если:

1. метод должен изменять структуру;
2. структура большая, и копирование дорого;
3. структура содержит mutex или другие нескачиваемые поля;
4. нужно единообразие API, если другие методы уже используют указатель.

Пример:

```go
type Counter struct {
 count int
}

func (c *Counter) Inc() {
 c.count++
}

func (c Counter) Value() int {
 return c.count
}
```

Использование:

```go
c := &Counter{}

c.Inc()
c.Inc()

fmt.Println(c.Value()) // 2
```

## 16. Встраивание структур

Go поддерживает встраивание, или embedding.

Встраиваемое поле объявляется без имени, только с типом.

```go
type Address struct {
 City string
}

type User struct {
 Address
 Name string
}
```

Поля и методы встроенного типа «продвигаются» во внешний тип.

```go
u := User{
 Address: Address{
  City: "Berlin",
 },
 Name: "Alice",
}

fmt.Println(u.City) // Berlin
fmt.Println(u.Name) // Alice
```

Фактически `City` — это поле вложенной структуры `Address`, но к нему можно обращаться так, будто оно находится прямо в `User`.

---

## 17. Встраивание — это композиция, а не наследование

Встраивание в Go не является наследованием.

Если `User` содержит `Address`, это не значит, что `User` является типом `Address`.

```go
type Address struct {
 City string
}

type User struct {
 Address
 Name string
}
```

`User` содержит `Address`, а не наследует его как подтип.

То есть:

```go
var u User
var a Address

// a = u // нельзя
```

Встраивание нужно для композиции поведения и повторного использования полей и методов.

---

## 18. Конфликты имён при встраивании

Если несколько встроенных типов содержат поля с одинаковым именем, возникает конфликт.

```go
type A struct {
 Name string
}

type B struct {
 Name string
}

type C struct {
 A
 B
}
```

Обращение:

```go
c := C{}

// fmt.Println(c.Name) // неоднозначно
```

Нужно обращаться явно:

```go
fmt.Println(c.A.Name)
fmt.Println(c.B.Name)
```

---

## 19. Продвинутые поля нельзя использовать в литералах

Продвинутые поля работают при чтении и записи:

```go
u.City = "Paris"
```

Но в композитных литералах нужно использовать реальные имена полей.

```go
u := User{
 Address: Address{
  City: "Berlin",
 },
 Name: "Alice",
}
```

Нельзя использовать продвинутое поле напрямую:

```go
// u := User{City: "Berlin"} // ошибка
```

---

## 20. Встраивание указателей

Можно встраивать не только значение структуры, но и указатель:

```go
type Address struct {
 City string
}

type User struct {
 *Address
 Name string
}
```

Тогда методы с указательным получателем у `Address` будут доступны через `User`.

Но если встроенный указатель равен `nil`, вызов продвинутого метода может привести к panic.

```go
var u User

// u.City = "Berlin" // panic, если Address равен nil
```

Поэтому при использовании встраивания указателей нужно следить за инициализацией.

---

## 21. Анонимные структуры

Иногда структуру можно объявить без имени.

```go
response := struct {
 Code    int
 Message string
}{
 Code:    200,
 Message: "OK",
}

fmt.Println(response.Code)    // 200
fmt.Println(response.Message) // OK
```

Анонимные структуры удобны для:

- тестов;
- временных данных;
- небольших JSON-ответов;
- локальных структур, которые не нужно переиспользовать.

Пример с JSON:

```go
data := []byte(`{"code":200,"message":"OK"}`)

var response struct {
 Code    int    `json:"code"`
 Message string `json:"message"`
}

err := json.Unmarshal(data, &response)
if err != nil {
 log.Fatal(err)
}

fmt.Println(response.Code)    // 200
fmt.Println(response.Message) // OK
```

---

## 22. Структуры и функции-конструкторы

В Go нет встроенных конструкторов. Обычно используют функции вида `New...`.

```go
type User struct {
 Name string
 Age  int
}

func NewUser(name string, age int) *User {
 return &User{
  Name: name,
  Age:  age,
 }
}
```

Использование:

```go
u := NewUser("Alice", 30)
```

Функция-конструктор полезна, когда:

- нужно проверить входные данные;
- нужно задать значения по умолчанию;
- структура имеет сложную инициализацию;
- нужно скрыть внутреннее устройство типа.

## 23. Память и выравнивание

Поля структуры хранятся в том порядке, в котором они объявлены.

На практике компилятор и рантайм могут добавлять выравнивание, поэтому размер структуры не всегда равен сумме размеров полей.

Например:

```go
type A struct {
 a bool
 b uint64
 c bool
}
```

Такая структура может занимать больше места, чем ожидается, из-за выравнивания.

Иногда более компактный порядок полей выглядит так:

```go
type A struct {
 b uint64
 a bool
 c bool
}
```

Но это уже вопрос оптимизации и особенностей реализации. Для большинства программ порядок полей выбирают ради читаемости, а не экономии нескольких байт.

---

## 24. Практические рекомендации

### 1. Используйте именованные поля в литералах

Лучше:

```go
p := Point{
 X: 10,
 Y: 20,
}
```

Чем:

```go
p := Point{10, 20}
```

Именованные поля безопаснее при изменении структуры.

---

### 2. Проектируйте структуры так, чтобы нулевое значение было полезным

Хороший пример:

```go
var b strings.Builder
b.WriteString("hello")
```

Нулевое значение уже можно использовать.

---

### 3. Используйте указатели, если нужно изменять структуру

```go
func (u *User) SetName(name string) {
 u.Name = name
}
```

---

### 4. Не используйте встраивание как наследование

Встраивание — это композиция.

Если тип содержит другой тип, это отношение «имеет», а не «является».

---

### 5. Не перегружайте структуру полями

Если структура начинает отвечать за слишком многое, лучше разбить её на несколько типов.

---

### 6. Осторожно копируйте структуры с mutex

Если структура содержит `sync.Mutex`, копирование может привести к ошибкам.

Обычно такие структуры используют через указатель.

---

### 7. Помните, что теги не проверяются компилятором

Например:

```go
type User struct {
 Name string `json:"name"`
}
```

Компилятор не проверит, правильно ли вы написали тег. Ошибки в тегах обычно проявляются только во время сериализации или десериализации.

---

## 25. Частые ошибки

### 1. Забыть передать указатель, если нужно изменить структуру

```go
func setName(u User) {
 u.Name = "Bob"
}
```

Здесь изменяется копия.

Правильно:

```go
func setName(u *User) {
 u.Name = "Bob"
}
```

---

### 2. Использовать позиционный литерал для большой структуры

```go
u := User{1, "Alice", "alice@example.com", true}
```

Если порядок полей изменится, код может сломаться или вести себя неправильно.

Лучше:

```go
u := User{
 ID:    1,
 Name:  "Alice",
 Email: "alice@example.com",
}
```

---

### 3. Ожидать, что структура со срезом сравнима

```go
type User struct {
 Tags []string
}
```

Такую структуру нельзя сравнивать через `==`.

---

### 4. Думать, что неэкспортируемые поля попадут в JSON

```go
type User struct {
 name string
}
```

Поле `name` не экспортируется, поэтому `encoding/json` его игнорирует.

---

### 5. Злоупотреблять встраиванием

Встраивание может сделать структуру сложнее для понимания.

Если связь между типами не очевидна, лучше использовать обычное именованное поле:

```go
type User struct {
 Address Address
 Name    string
}
```

---

## 26. Небольшой практический пример

```go
package main

import (
 "encoding/json"
 "fmt"
)

type User struct {
 Name     string `json:"name"`
 Email    string `json:"email"`
 Age      int    `json:"age,omitempty"`
 Password string `json:"-"`
}

func NewUser(name, email string, age int) *User {
 return &User{
  Name:  name,
  Email: email,
  Age:   age,
 }
}

func (u *User) SetAge(age int) {
 u.Age = age
}

func main() {
 u := NewUser("Alice", "alice@example.com", 30)

 u.SetAge(31)

 data, err := json.MarshalIndent(u, "", "  ")
 if err != nil {
  panic(err)
 }

 fmt.Println(string(data))
}
```

Пример вывода:

```json
{
  "name": "Alice",
  "email": "alice@example.com",
  "age": 31
}
```

Поле `Password` отсутствует, потому что оно не было задано, но даже если бы оно было задано, тег `json:"-"` исключил бы его из JSON.

---

## Важные оговорки

- Поведение выравнивания памяти зависит от реализации, поэтому не стоит строить на нём логику программы.
- Встраивание указателей требует аккуратности, особенно если встроенный указатель может быть `nil`.
- Если структура содержит `sync.Mutex` или другие примитивы синхронизации, её обычно не копируют.
- Для сериализации важно учитывать экспорт полей и теги.
